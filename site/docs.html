MoonViz 使用文档

本文覆盖引擎的全部对外集成面：CLI 行协议、Node SDK、MCP Server 与 Agent SKILL。所有路线共享同一份 .mbt.md 事实源与同一套双 Gate 校验。

总览

MoonViz 是用 纯 MoonBit 实现的原型设计基础引擎。核心不变量：

  • 单一事实源 —— 一份 .mbt.md（MoonBit literate 源码）就是整个项目。引擎不维护第二份状态。
  • 双路线编辑 —— 人类画布操作与 Agent 修改都回写同一源文件；导出分 export-mbt-human / export-mbt-agent 两个 Gate。
  • 预览从源重建 —— 任何视觉输出（SVG / 画布）都是对源的即时渲染，不存在旁路缓存。
  • 加密分发 —— 文档以 DDP 容器交付：DDP1 加密（Argon2id + XChaCha20-Poly1305）或 DDP2 免密（zstd + CRC32）。
引擎目录结构：core/（内核）· cli/（行协议 CLI）· mcp/（MCP Server）· decl/（声明库）· ddp/（Rust 编解码器）· sdk/node/（Node SDK）· playground/（实验场）· SKILL.md（Agent 技能）。

快速开始

前置条件

  • MoonBit 工具链：需要 moon 可执行文件（~/.moon/bin/moon 或 PATH 中）。
  • DDP 加解密需先构建 Rust 工具：cd moonviz/ddp && cargo build --release（产物 ddp/target/release/ddp_codec）。

跑通第一条链路

cd moonviz

# 有状态会话：stdin 一行命令 → stdout 一行 JSON
moon run --target native cli

# 会话内：
template login t_login 390 844        # 从模板建画板
update t_login welcome_title text="欢迎回来"
flow t_login t_home login_btn         # 点击 login_btn → 跳转 t_home
export-mbt-human                       # HumanGate 校验，返回 canonical .mbt.md
exit

每条命令返回一行 JSON：{"ok":true,...}；导出命令额外携带 mbt（完整源码）、flows、artboards 等字段。

无会话渲染 / 校验

# 渲染（AgentGate 级重载：MBT 完整重建）
render-mbt-b64 <base64(mbt)>
# → {"ok":true,"entry":"t_login","flows":[...],"artboards":[{id,width,height,svg,nodes}]}

# 只校验不渲染
validate-mbt-b64 <base64(mbt)>
# → {"ok":true,"entry":...,"revision":...,"blockKinds":{...}}

CLI 行协议

协议约定：换行分帧 JSON——stdin 每行一条命令，stdout 每行一个 JSON 值。一个 CLI 进程 = 一个有状态 Project 会话；exit 或 stdin EOF 结束会话。

moon run --target native cli      # 在引擎根目录（含 cli/moon.pkg）执行

为什么用 base64？ MBT 源码是多行 Markdown，用 base64 编码后可安全塞进单行帧，避免换行分帧歧义。

Node SDK（@moonviz/engine-sdk）

SDK 是纯传输 / 编排层：拉起 CLI 子进程、编码命令、解析 JSON 行——不缓存、不建第二事实源。要求 Node ≥ 18，ESM。

import { MoonViz, Project, DDP, build } from '@moonviz/engine-sdk';

// 1. 引擎客户端（moonvizDir 指向引擎根，含 cli/moon.pkg）
const engine = new MoonViz({ moonvizDir: '../moonviz' });

// 2. 低层：直接下发一批命令（同一会话）
const templates = await engine.run(['list-templates']);

// 3. 高层：Project 构建器（累积命令，导出时一次执行）
const mbt = await build(engine, p => {
  p.template('login', 't_login', 390, 844);
  p.template('dashboard', 't_home', 390, 844);
  p.update('t_login', 'welcome_title', { text: '欢迎回来' });
  p.flow('t_login', 't_home', 'login_btn');
});                       // → canonical .mbt.md 文本

// 4. 渲染（AgentGate 重载）
const r = await engine.render(mbt);        // { ok, entry, flows, artboards }

// 5. 双 Gate 操作
const r2 = await engine.applyHumanOp(mbt, op);   // Human 编辑
const r3 = await engine.applyAgentOp(mbt, op);   // Agent 编辑

// 6. DDP 容器
const { bytes } = await DDP.encrypt(mbt, 'pass');   // DDP1 加密
const free = await DDP.encrypt(mbt, '');            // DDP2 免密
const back = await DDP.decrypt(free.bytes);         // → { mbt }

WASM SDK（moonviz-engine-wasm）

引擎的 WebAssembly GC 构建：渲染与校验管线跑在进程内 wasm 实例里——零工具链、零子进程、零服务器。通过 JS String Builtins，MoonBit String 与宿主字符串直接互通。API 面：render / validate / applyOp（双门禁）/ exportHtml / listComponents / listTemplates / listThemes / listTokens / listOps，以及会话面 sessionOpen/sessionApply/sessionConstrain/sessionAutoFix/sessionGenerateResponsive/sessionTap/sessionSave（i32 句柄；改文档面成功信封带 canonical mbt，宿主须保存供下次 open 用）。

classic 字符串 ABI 已契约化：对象布局双判别式、UTF-16LE 编码、槽协议全文档见 docs/wasm-abi.md，CI 断言防漂移。

标准 wasm 产物（宿主中立）：moon build --target wasm 产出纯 WASM MVP 模块（线性内存、0 imports、(i32)->i32 签名、导出 memory）——不依赖任何宿主特定提案，wasmtime/wasmi 等任何规范运行时均可实例化。字符串 ABI：对象 = [4B refcnt][4B header][len×UTF-16LE]，header = (kind<<30)|(shift<<28)|len。

MCP Server

mcp/ 是标准 stdio JSON-RPC MCP Server，可直接接入 Claude Desktop、ZCode、Cursor 等任何 MCP 客户端。

引擎同时上架 mooncakes.io（MoonBit 官方包中心）：moon add asdshuaishuai/moonviz 后经 sdk/ 门面（@sdk.new/apply/validate/render_svg/canonical）在 MoonBit 工程内直接内嵌引擎。

SKILL 技能（Agent 集成）

引擎根目录的 SKILL.md 是给 coding agent（ZCode / Claude Code / Codex 等）的操作规范。将引擎仓库加入 Agent 可访问路径，或在技能目录中引用它，Agent 即可按规范安全驱动引擎。

SKILL 约定的核心规范

  • 事实源纪律：任何修改必须回写 .mbt.md，禁止只改画布或只改内存态。
  • 双 Gate 语义：模拟人类操作用 Human 路线（结构违规硬阻断）；程序化批量修改用 Agent 路线（语义级校验 + debt 记账）。
  • 操作入口：优先 MCP 工具；无 MCP 环境时退回 CLI 行协议；Node 宿主用 SDK。
  • 渲染即验证：每次修改后用 render_mbt / render-mbt-b64 重建视觉并比对预期。
  • 红线：不缓存渲染结果、不绕过 Gate 导出、不直接改 DDP 二进制。
  • 组件规范与返回：五类规范（按钮留白 / 圆角档 / 列表分割线 / 撞色零容忍 / 横平竖直）由 critique + auto_fix 闭环；返回类节点 tap 内置返回上一层，非入口画板须有出边 flow 或返回节点。
# 在 Agent 技能目录中挂载（示例：软链 SKILL.md）
ln -s /path/to/moonviz/SKILL.md ~/.zcode/skills/moonviz/SKILL.md

二进制分发与工具链风险

预编译二进制（CLI 1.26MB / MCP 1.10MB）自包含、仅链系统 libc——moon 工具链只存在于编译时。MCP 走 npx moonviz-mcp 平台包；Node SDK 安装 moonviz-bin-<platform> 后自动发现预编译 CLI（或 MOONVIZ_CLI_BIN），全程零工具链。CI 与 Pages 构建使用 latest 工具链（历史锁定版本目录会从下载 CDN 下架），每次构建以全量 `moon test` + CLI/MCP 冒烟挡板验证；已发布产物永久冻结不受影响。平台 tarball 同时归档于 GitHub Releases（engine-v* tag）——分发不依赖 npm 单渠道。

DDP 容器（Rust ddp_codec）

DDP 是文档分发格式，由引擎仓库内独立的 Rust 工具 ddp_codec 编解码。协议：stdin 单行 JSON → stdout 单行 JSON。

格式构成用途
DDP1Argon2id 密钥派生 + XChaCha20-Poly1305 AEAD带密码加密分发；错密码 → 认证失败
DDP2zstd 压缩 + CRC32 完整性校验（无加密）免密场景：预览、CI、演示
# 加密（DDP1）
echo '{"operation":"encrypt","mbt_b64":"…","password":"p@ss"}' | ddp_codec
# → {"ok":true,"ddp_b64":"…"}

# 免密（DDP2）：password 传空串
echo '{"operation":"encrypt","mbt_b64":"…","password":""}' | ddp_codec

# 解密
echo '{"operation":"decrypt","ddp_b64":"…","password":"p@ss"}' | ddp_codec
# → {"ok":true,"mbt_b64":"…"}

组件规范 norms（0.1.9 起）

弱模型最常产出「能用但不精致」的原型。组件规范是组件质量的单一定义点（core/norms.mbt），五类根因各有检测 + auto_fix 一键修复，critique 第 9 维（norms）给 Agent 反馈。只走软路径——critique/fix 软纠偏，不改双门硬约束：

规范规则auto_fix
按钮不卡文案操作组件（button/chip/tag/fab）文案与边缘留白：宽 ≥ 文案宽+24（左右各 12），高按组件档位（chip 28 / tag 22 / fab 56；多行按行数计高）建议尺寸（critique 自带）
圆角档方正圆润族 8px 档；超出 高/2 收敛为胶囊；avatar 正圆 999；app_bar/tab_bar/list_item/divider 占满画板宽时圆角归 0收敛到档位
列表必须有分割线≥3 行 list_item 齐缝连排且整段无 divider = 裸列表每行行底插入 1px divider 子节点（不参与 v1 重叠/包含检查，零门风险）
撞色零容忍文字对有效背景（自身实底 → 最近实底祖先 → 白底）的 WCAG 对比度 < 2.0 即同色系严禁（黑底黑字/白底白字）；品牌绿白字（≈2.4）不误伤按背景亮度翻转文字黑/白
横平竖直rotate 非 90° 倍数归零（与圆角档、对齐网格共同构成几何标准）归零

闭环：critique 偏差计分并自带建议尺寸 → auto_fix 一键规范预修（不动 fill/hug 策略）→ list_components 每条目携带 norm 字段。规范走指导与修复，不做硬门。

内置返回导航（0.1.9 起）

返回交互是必须的——不再由各宿主自发实现，而是引擎内置语义：CLI / SDK / MCP / 嵌入 runtime 全部免费获得。

能力语义
返回类节点 tap 兜底tap 解析链 flow → marker → 内置返回：命中 back/prev/返回/← 类节点且无 flow/marker 绑定时，弹导航栈返回上一层（栈底原地不动）
返回热区随清单导出interactions 导出包含返回类节点（"builtin":"back"）——宿主热区直接消费引擎数据，无需自带启发式词表
卡死页校验多画板文档中非入口画板无出边 flow 且无返回类节点 = 用户会卡死——norms 维度直接判偏差

测试锚点：core/norms_wbtest.mbt（规范五类）、返回语义随交互运行时测试。

动效系统（dev 线，精致感/流畅性）

动效不是装饰，是交互反馈的一部分。令牌单一来源：animation.mbt 的时长刻度（120/240/360ms）与缓动曲线（Easing::css_value，含 spring/bounce 的 cubic-bezier 等价式）经 motion_tokens_css() 注出 :root 变量——引擎与导出面共用同一节拍，引擎侧不散落手写贝塞尔。

能力语义
方向感知转场navigate 前进（+1 滑入）/ back 返回（−1 反向）/ tab 纯淡入（0）；fill 用 backwards，动画结束即交还 transform 给按压反馈
按压反馈交互节点 :active 时 spring 回弹缩放（fill-box 居中）——SVG 原型的触感来源；组件状态的 fill 切换走引擎缓动，不再生硬跳变
入场阶梯画板子节点 24ms 步进依次浮现（前 8 个），克制不抢戏
开屏页推断export_html 开在导航流天然起点（未被任何 flow 指向的画板），不随 Map 遍历序漂移到任意画板
流畅性细节ESC = 返回（与内置返回导航语义对齐）；画板切换平滑回顶；tab hover 抬升 + 活动态投影
微交互动效set_text 文字更新 tick 滑入 / setState 状态切换 pop 回弹 / 页面入场 boot 淡入——令牌同源，prefers-reduced-motion 全覆盖
动作面补齐haptic（触觉反馈 toast）/ play_sound（音效提示）进导出绑定表——此前导出面静默丢弃；submit_form 的 spec 语法扩展列入后续
无障碍系统开启 prefers-reduced-motion 时全部动效关闭——精致感不含强制动；:focus-visible 键盘焦点可见；color-scheme 声明暗色控件

测试锚点：core/export_wbtest.mbt（动效令牌/方向转场/按压反馈/入场推断）。

生成式 UI 与 Agent 执行策略（dev 线）

理念：Agent 声明意图，引擎生成界面（genUI 第一公民）；工具模式完整保留作为兜底（以前的不抛弃）——自由形态画板、模板之外的布局、外科手术式单节点修改、探查，本来就是工具面的职责。页面结构、组件选择、间距规范、视觉一致性由引擎负责；阶梯是按成本排通道，不是按权限设门槛（逐层下探是正确行为而非失败）。执行阶梯（从顶层开始）：

级入口语义
第一级generate（MCP 工具 / CLI 命令）一句话意图（"登录页 dark" / web 落地页）→ 引擎选模板 + 规范自愈（auto_fix）→ 报告信封：autofix（引擎修了什么）/ missing（该类页面还缺什么）/ score（A–D 质量分）/ 确定性 alternatives。意图解析为确定性关键词分类（中英/主题/设备暗示），引擎无 LLM、同输入恒同决策；组合意图（"登录+注册"，+ 连接 ≤4 段）展开为多画板 + 相邻自动导航流（出口启发：就地找目标语义节点，找不到合成前往按钮），纯主题段（dark）全局生效不生成板
第二级batch_apply / CLI ops-batch-b64确定的精修一批一次提交（换行分隔 ops，base64，≤64）——顺序执行、遇错即停、回传断点索引供续批
兜底（工具模式）template / 全部单条工具与 op完整保留：模板之外的自由形态构建、外科手术式修改、微调与探查——55 工具 / 27 op 一个不少

反模式（限定在 genUI 已覆盖的场域——工具模式本身不是罪）：标准页面逐节点摆放（模板已覆盖）；为生成内容手算坐标（布局归引擎）；已知清单拆 N 次单调用（应打包一批）；不看 score/missing 就交付（报告就是评审环）。拿不准就问：模板/配方是否已表达这个意图？是 → genUI；否 → 用工具自由构建——那正是兜底存在的意义。测试锚点：core/generate_wbtest.mbt、cli/main_test.mbt（generate/ops-batch 协议）。

Webview 自渲染（desktop/，dev 线，客户端引导模型）

引擎直接为客户端提供渲染能力，但不能自己取用：引擎无 UI、无窗口、不自行获取渲染面——自渲染必须依托客户端的引导。客户端（Tauri / Electron / 任意原生壳）拉起引擎、指定渲染源、承接结果，渲染本身零客户端代码：

表面条件行为
客户端 webview客户端有自己的 webview把渲染产物（MOONVIZ_OUT，缺省 moonviz-render.html）载入客户端 webview 即是活原型——自包含交互 HTML（画板切换/导航流/toast/状态多态运行时内嵌）
系统兜底原生环境无 webview引擎直接调用系统层渲染并返回结果：产物写盘，写盘也不可用时把自包含 HTML 打到 stdout（渲染结果即返回值）

宿主面：CLI/MCP 直接可用；wasm 宿主经 session_generate（intent+name，变更回传 canonical mbt）+ op 面的 autofill（session_apply_agent 直达）——生成式管线全渠道同构。

无引导即惰性：未设 MOONVIZ_DOC 时引擎只回 usage 信封，不渲染、不写文件（CI 硬门断言）。渲染链路 .mbt.md → load_mbt_project → export_html 全程进程内、纯 MoonBit——无 sidecar、无上层框架依赖。抽象统一层 desktop/shim/mv_shim.h：引擎侧只有系统 I/O（mv_getenv/mv_read_file/mv_write_file/mv_free），单文件纯 C 标准库实现、三平台无差异零框架链接；webview 的创建/窗口/事件全部属于客户端。开关：MOONVIZ_DOC（渲染源，引导必需）· MOONVIZ_OUT（产物路径）· MOONVIZ_SMOKE=1（无头自检，CI 硬门）。
